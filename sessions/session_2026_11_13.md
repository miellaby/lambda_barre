# Session 2026-11-13 (suite 2) — conséquence rétro-causale en unités de salve inversées

## Décision (avec l'utilisateur)

La séquence enregistrée devient pleinement rétro-causale, calquée sur le
layout legacy (`LEGACY-AI` : `eos_pos = seq_steps*SALVE_TOKENS + _INTERO_IDX`,
dernier token de la séquence legacy) :

    contexte (ordre normal) | conséquence rétro-causale | action de décision

- contexte : `s0+a0 .. a_{n_ctx-1}+s_{n_ctx}` (`ctx_len` tokens, `s_{n_ctx}` sans action) ;
- conséquence : unités de 16 tokens pour `k = seq_steps .. n_ctx+1` :
  `s_k` tokens d'état **inversés** (token 12 en premier), puis `a_{k-1}`
  (3 tokens, ordre interne normal) → `s26, a25, s25, a24, ..., s5, a4` ;
- **token de dénouement** = token 12 de la première unité (`s_{seq_steps}`),
  à `eos_pos = ctx_len = conseq_start` : premier token après le contexte,
  prédit/échantillonné juste après le contexte (predict_denouement lit la
  dernière ligne du contexte, inchangé). 6 slots, canal dédié (0,0,1,0) ;
- action de décision `a4` : 3 derniers tokens (`action_pos`).

`seq_len = 429` pour seq_steps=26, n_ctx=4 (ctx_len=77, conseq_len=349,
action_pos=426). `a_{seq_steps}` n'est pas enregistrée. Terminologie branche
refonte : **token de dénouement** (pas « EOS »).

## Implémenté

- `brain.py` : `compute_seq_layout` (conseq_start = eos_pos, conseq_len =
  (n_imagine-1)*16+13), `compute_salve_positions` (unité j : s_k→k, a_{k-1}→k-1),
  `build_target_tables` (offset<13 → token 12-offset, sinon token offset),
