## Notes design

- µ (tête MSE) = moyenne conditionnelle, pas le meilleur dénouement ; le couple (K tirages dans la boule T autour de µ, élection par max relief) retrouve un dénouement meilleur que la moyenne ; l'observé ne gagne que s'il bat strictement l'élu.
- Sens du décalage brain-off acté : `(s_{n-k}, a_n)` (action après l'état). BACKLOG.md:221 et session_2026_11_12 décrivent l'autre sens — specs non à jour, laissées en l'état.

- **Échantillonnage du dénouement en 2 étapes** (`sample_denouements`, brain.py) : l'ancien algo était un **top-p** (masse softmax cumulée ≤ 0.9) sur les K=8 tirages à T=0.3 — avec K faible la masse n'atteint jamais 0.9 avant la fin, le filtre gardait tout, donc élection « au hasard dans la boule ». Remplacé par un **top-n absolu** : étape 1 = garder les `eos_top_n` (défaut **3**) tirages de plus haut logp (argsort + scatter en coordonnées originales — l'ancien bloc mélangeait coordonnées triées et originales, bug latent rendu visible par le top-n), étape 2 = argmax relief parmi ce noyau. `top_p`/`eos_top_p` supprimés, `top_n: int | None` dans la signature. Vérifié sur chkpt (coreset 142) : p_elu 0.000→**0.18–0.39** (seqs 16/42/141/12/106), élu moins extrême (max|slot−0.5| 0.50→0.41–0.49 à top_n=3). Tests : 21 passed, `test_sample_denouements_shapes_and_election` inclut top_n=1 → p_elu = 1 déterministe.

- **eos_top_k 8 → 64** (défaut `Brain`) : avec K=8, les « top_n plus probables » restaient à ±0.4 de µ et l'élu pouvait avoir un relief très négatif (vu -0.263 sur seq #30 avec l'ancien top-p/K=8). Avec K=64, top_n=3 : sur seq #30, 200 seeds → relief_elu min -0.060, moyenne +0.221 (relief_mu = -0.031), p_elu ~0.3 ; l'élu seq#30 = [0.47, 0.44, 0.69, 0.46, 0.67, 0.58] au lieu de [0.10, 0.80, ...] clampé. Coût négligeable (64 vecteurs de 6 floats). 21 tests passés.
- Diagnostic relief : `relief_score` p=8 ≈ max flou des slots → l'argmax relief pousse toujours UN canal vers 0/1 ; c'est inhérent à la métrique (aussi utilisée pour la surprise), pas un bug de l'élection. L'élection reste : argmax relief restreint aux top_n plus probables.

- **Arrivée précoce encodée dans l'EOS** (`_eos_slots_of_window`, forme fermée) : `r = P − poids_chemin·A + poids_arrivee·max(0,P)·early`, avec `early = Σ w_k·σ((c[fin]−c[k])/tau)/Σ w_k`, `w_k = decay^(k−n_ctx−1)`, `tau = _EOS_ARRIVEE_TAU = 0.1` — fraction douce du temps passé sous le niveau final, sans seuil procédural. `poids_arrivee` défaut **0.5**, câblé comme `poids_chemin` (brain.py, config.toml `eos_poids_arrivee`, config.py, main.py, wm_theater.py, wm_manager.py). Vérifié : #15 (relevement k=16) slot douleur 0.896 > #14 (k=17) 0.887 > #10 (k=21) 0.849 — monotone du timing. 21 tests passés.
- **Script réutilisable `.tmp/recompute_eos.py`** : recalcule le token dénouement de toutes les séquences du buf chkpt avec la formule courante (dry-run par défaut, `--show 10,15`, backup `<buf>.bak`). Appliqué sur buf_ckpt.pt : 211/227 modifiées, max Δslot 0.0455.

- **poids_arrivee 0.5 → 2.0** (défaut partout : `_EOS_POIDS_ARRIVEE`, config.toml, main/wm_manager/wm_theater) : à 0.5 le spread temporel sur #28→#35 était 0.049 (tanh + P constant); à 2.0 spread = 0.109 (#28=0.737, #30=0.774, #33=0.820, #35=0.846) sans saturation; à 4.0+ tanh sature vers 0.93+. `buf_ckpt.pt` recalculé avec le script (211/227, max Δslot 0.117, backup original conservé dans `buf_ckpt.orig.pt`). 21 tests passés.

- **Poids du groupe EOS = ctx_len** (`build_target_tables`) : le dénouement pèse autant que tout le contexte (en langage naturel, chaque token du prompt aurait un poids) — per-slot `ctx_len/6` sur la ligne `eos_pos-1`. Trajectoire et décision restent à 1.0 chacune. Avec seq_steps=26/n_ctx=13 : EOS = 221, soit ~99% de la loss (sqm/wsum). Test `test_target_tables_prompt_context` mis à jour (eos sum == ctx_len). 21 tests passés. Dropout CFG de l'eos proposé puis retiré à la demande de l'utilisateur : l'eos reste inconditionnellement dans l'entrée d'entraînement (teacher forcing).

- **Masque : 1*dénouement = 1*contexte** (`build_salve_mask` + `cache_forward`, models.py) : la colonne eos (index ctx_len) reçoit la **somme des biais de toutes les colonnes contexte** (75.55 = 75.55 pour ctx_len=221, boost=ln2) au lieu du simple gain plein. Causalité OK, cache==forward (1.2e-6). En softmax l'eos domine alors quasi totalement (biais additif en log-espace : exp(somme) >> somme(exp)) — si tu veux 50/50 en proba, il faudrait log-sum-exp du contexte à la place. Test `test_wm_single_mask_is_causal` : assertion eos == somme contexte ajoutée. 21 tests passés.
- **Loss : tiers égaux confirmés** — génération dans l'ordre eos, rétro-conséquence, action-décision → 33% chacun (groupes de poids total 1.0 : eos {eos_pos-1}, traj [eos_pos, action_pos-1), dec [action_pos-1, seq_len-1)). La variante eos=ctx_len a été retirée.

- **Policy : RL offline pondéré par le return** (`_policy_step`) : le poids par séquence devient `w = p_elu · relu(relief(eos_elu))` — confiance de l'élu × return du dénouement élu (relief_score, p=8), les returns négatifs ne contribuent pas. La cible reste a* (action de décision de la conséquence générée depuis l'élu). 21 tests passés. Le continuum du dénouement fait le job s'il est bien ordonné (vérifié monotone #28→#35 avec poids_arrivee=2.0).
- Backlog (time-event) : séquences symboliques à longueur variable = nombre d'extrema du geste, délai en slot de consigne, pas d'horloge. Label amorçage : onset d'un run d'extrema à n_ctx + signe conforme au geste futur. Filtrage dataset : garder pôles (immédiat / neutre-vrai), lâcher le tard.

- **Impact-proportional training WM réintroduit** (ADR-0001: impact = |relief(seq)|) : `wm_impact_floor` rebranché comme vrai param de `Brain` (sorti de `**_legacy`), `_wm_masked_mse`/`_wm_loss_impl` acceptent `seq_weights`, et `_train_wm_batch` pondère chaque séquence par `max(|relief(seq)|, wm_impact_floor)`. Vérifié : seq#107 (amorçage) relief +0.70 → poids 0.70 ; seq#95 relief +0.05 → poids 0.25 (floor). 21 tests passés.
